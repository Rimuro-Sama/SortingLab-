Comparações e escritas são exatas e reproduzíveis. O tempo é medido no seu navegador, com a instrumentação do laboratório ligada: use-o para comparar algoritmos entre si, não como medida absoluta de velocidade. Varia entre execuções e entre máquinas, e os navegadores arredondam o relógio (cerca de 0,1 ms), então tempos muito pequenos são pouco confiáveis.

Sobre o projeto

O Sorting Lab nasceu de um trabalho de faculdade em Java que ordenava 150 mil nomes (OrdenacoesNomes-Java). Aqui a ideia ganhou uma interface: dá para ver cada algoritmo, comparar o custo em diferentes tipos de entrada e ordenar textos em português.

Como funciona

  • Cada algoritmo é escrito uma única vez e passa todas as comparações e escritas por um objeto que conta e grava eventos. O visualizador reproduz os eventos, o benchmark só conta, e os testes automáticos usam o mesmo código.
  • Os dados são gerados a partir de uma semente: a mesma semente produz sempre o mesmo array, então a comparação entre algoritmos é justa.
  • O benchmark roda num Web Worker, para não travar a página.
  • Textos são ordenados com Intl.Collator('pt-BR'), que trata acentos corretamente (com a comparação simples, "Álvaro" iria para depois de "Zélia").

Limites

  • Medir tempo em JavaScript é impreciso: depende do navegador, da máquina e do aquecimento do motor. Por isso a tabela mostra também comparações e escritas.
  • Os algoritmos O(n²) ficam muito lentos acima de ~20.000 elementos.
  • A comparação com Array.prototype.sort do navegador é só uma referência: ele é código nativo, sem a instrumentação.
